# AI员工工作台产品需求文档

版本：0.3　日期：2026年10月2日　产品代号：My Workbench

本产品面向独立创作者与开发者，在 macOS 上集中管理员工、工具、任务和产物。本次开发范围覆盖 M0 至 M4：本地执行、员工与产物管理、远程生成、AI拆解及依赖协作，按各阶段验收推进。用户始终能看到任务由谁执行、使用什么工具、输出在哪里，以及是否已经验收。

## 1 产品目标与范围

原始需求来自用户提供的《AI员工系统规划》对话：原生 macOS 软件、接入各种 CLI 和 AI 工具、按部门协同、跨员工交接，以及视频、音频、音乐、开发和设计资源整合。对话中的多语言后端与模型名单属于技术建议，不作为首版必须实现的约束。

基础闭环的验证目标是：用户无需切换多个终端，即可注册一个可执行工具、绑定员工、创建任务、观察真实日志、处理失败并验收结果。产品定位为个人工作台，界面以项目和任务为中心。自由对话只作为未来的任务入口。

| 阶段 | 交付范围 | 通过标准 |
| --- | --- | --- |
| M0 需求与设计 | PRD、开发方案、可点击原型 | 范围、关键状态与验收用例可评审 |
| M1 本地基础闭环 | SwiftUI 客户端、工具与员工、串行任务、日志、持久化、人工验收 | 本地样例命令真实执行，重启后记录存在 |
| M2 MVP 完整版 | 产物归档、超时与进程树取消、重试、结构化人工交接、Codex 适配 | 首版全部 P0 用例通过 |
| M3 远程制作 | ComfyUI API 与 SSH 隧道、远程队列与回收 | 指定服务器上的一条工作流通过实际验收 |
| M4 自动协作 | AI 拆解、依赖调度、审核返工 | 多员工协作样例可复现且不重复执行 |

首版不包含账户与计费、多租户、向量数据库、本地大模型部署、复杂组织权限、完整 PTY 终端、自动发布和 App Store 上架。普通 API 或 CLI 注册不代表已经接通某个付费生成服务。

## 2 用户与典型任务

主要用户是同时管理多个制作项目的独立工作者。用户既是任务提出者，也是结果验收人；AI员工是角色配置和工具能力的组合，并不意味着系统已经具备自主判断或协作能力。

| 部门 | 典型员工 | 输入与交付 |
| --- | --- | --- |
| 开发部 | 开发工程师、测试员 | 需求与代码目录；补丁、测试报告 |
| 视频部 | 编剧、分镜师、生成执行员、剪辑师 | 剧本与参考素材；分镜、候选片段、成片 |
| 音频音乐部 | 配音员、声音编辑、音乐制作员 | 文稿与音轨；配音、音乐、混音 |
| 设计部 | UI设计师、视觉设计师、PPT制作员 | 设计简报；设计文件、图片、演示稿 |

开发场景：用户选定项目目录，指定开发工程师和工具，提交任务；系统显示工作目录与参数，启动进程并展示日志。退出成功后进入“待验收”，用户检查产物后标记完成，或填写返工说明创建新一次执行。

视频场景：分镜员工把需求、参数、参考图和输出约束交给生成员工。MVP 先支持用户整理交接包；远程 ComfyUI 接入后再提交工作流并保存服务端任务编号。下载成功只代表技术产物已取得，画面、声音、人物连续性仍需人工验收。

不同项目的文件和交接记录归属各自项目。工具可复用，项目上下文不得自动混用。

## 3 工具与员工需求

| 编号 | 优先级 | 需求 | 可观察行为 |
| --- | --- | --- | --- |
| F01 | P0 | 注册本地 CLI | 填写名称、绝对路径、参数列表、非交互模式与超时 |
| F02 | P0 | 检测工具 | 检查可执行文件，用户主动运行版本命令；失败显示原因 |
| F03 | P0 | 员工档案 | 名称、头像、职位、工作区、职责、绑定工具；同区多人，独立新增与编辑 |
| F04 | P0 | 项目工作目录 | 用户选择目录；每次执行记录目录快照 |
| F05 | P0 | 创建任务 | 任务目标、员工、输入文本、参数和验收条件 |
| F06 | P1 | 员工停用 | 禁止新任务；已有记录保留 |
| F07 | P1 | 工具版本适配 | 保存最近检测版本与适配状态，升级后重新验证 |

工具路径不能依赖 Finder 启动 App 时的 shell PATH。可用“选择文件”指定二进制；工具参数采用列表编辑器，每项对应一个 argv 元素。输入占位符 {input} 替换为完整输入，{output} 替换为本次产物目录；替换后仍是单一参数，不进行 shell 展开。执行同时提供 MYWORKBENCH_OUTPUT_DIR 和 MYWORKBENCH_RUN_ID。空字符参数必须拒绝，不能静默截断。

“可执行”“版本检测成功”“账号已登录”“业务任务验收成功”是不同状态。首版检测成功不能显示为已验证全部能力。只支持交互 TUI 的工具提示暂不支持后台执行，引导使用其官方非交互入口。

每个工作区可以配置多位员工，多人可以共用工具，但姓名、职责、启停状态与头像分别保存。编辑档案保持员工编号和已有任务关联；执行快照保留当时的配置。头像支持姓名首字、预设符号及本地 PNG、JPEG、HEIC、WebP 图片，导入上限10MB，保存160像素缩略图；原图片移动或删除不影响头像。

职责说明在 M1 作为员工档案保存；M2 由专门适配器组装为输入上下文。通用执行器不擅自把说明拼入任意命令。

## 4 任务与执行需求

每个任务拥有稳定编号；每次执行生成独立 run 编号，记录工具与员工快照、输入、参数、开始结束时间、退出码及日志位置。重试与返工新增 run，不覆盖旧结果。默认同时执行1个任务，可以配置为2个；超出容量排队，每个执行编号只启动一次。

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| 草稿 | 任务尚未提交 | 保存、提交、删除草稿 |
| 排队 | 等待执行资源 | 启动、取消 |
| 执行中 | 进程正在工作 | 完成执行、失败、取消、超时 |
| 待验收 | 执行成功，结果待检查 | 验收通过、返工 |
| 已完成 | 用户确认交付达标 | 查看、人工发起下游任务 |
| 失败 | 非零退出或启动失败 | 查看原因、修正后新建执行 |
| 已取消 | 用户终止执行 | 查看已产生的结果、新建执行 |
| 超时 | 到达执行时间上限 | 查看日志、修正上限后重试 |
| 已中断 | App 退出或故障留下的运行记录 | 检查外部状态后手动重新执行 |

stdout 与 stderr 必须持续读取，界面批量刷新并保持响应；日志过多时显示最近部分，完整日志落盘。没有可信进度事件时使用不确定进度指示，不伪造百分比。队列进度可按完成步骤计数，并注明计数口径。

退出码为 0 进入待验收，不能自动标记业务完成。启动失败、权限不足、工具未登录、磁盘不足和网络失败展示可操作信息，不用一条“失败”笼统代替。

停止操作先发送温和终止信号，必要时升级结束本次执行拥有的进程树。远程任务需单独确认服务端取消结果；断开连接不代表服务器停止。M2 使用每次执行独立拥有的 POSIX 进程组；先发 SIGTERM，1秒后仍未退出则升级 SIGKILL，取消与超时保留各自终态。主动脱离进程组的守护程序不属于受支持的后台 CLI。故障退出后的旧作业需要检查，重启不能据记录猜测外部进程已停止。

## 5 产物交接与授权

产物中心按项目和任务归档，记录来源 run、文件相对路径、类型、大小和验收状态。每次执行独立目录保存完整日志与产物；返工不得覆盖旧目录。只自动收集本次产物目录中的普通文件，跳过符号链接；其他文件由用户主动选择导入。文本直接查看，图片、音视频使用系统预览，开发产物支持在 Finder 中定位。远程文件先展示位置和大小，用户主动下载。

结构化交接包包含：来源任务和 run、目标员工、目标说明、文件引用、参数、约束、已通过检查、待确认事项与验收标准。MVP 交接由用户发起，目标员工只有在交接确认后接收任务；自动拆解不在 M1 范围内。

默认不覆盖原始素材；返工保存新版本。文件内容和模型回复视为业务数据，不自动变成权限指令。若员工提出删除、发布、访问新目录或增加花费，需生成可审阅动作，并由用户明确批准。

本地任意 CLI 具有用户账户权限。工作目录限制只是路径管理，不能当作操作系统沙箱。用户在注册和运行前能看到真实可执行文件、参数及目录。AI CLI 应保留工具自身的权限控制；预设不包含绕过审批的选项。

凭证优先由工具自身登录管理，后续 API 密钥使用 macOS Keychain。工作台不复制 CLI 登录文件，不把密钥写入项目或交接包；日志需遮蔽工作台持有的密钥。收费服务调用前展示预算约束；无法取得精确价格时标记为未知。

## 6 工作室界面与质量要求

用户已选择AI工作室方向：员工分布在影像、声音、开发、视觉四个工作区，围绕中央项目桌协作。主界面采用可缩放的空间画布；点击员工、任务或项目对象，在当前空间浮出详情。工具架与素材盒在空间内展开，日常工作不依赖侧栏切页。

| 空间对象 | 主要内容 | 关键操作 |
| --- | --- | --- |
| 员工席位 | 姓名、职责、部门与绑定工具 | 展开档案，创建已选负责人的任务 |
| 桌面任务 | 标题、负责人、状态、执行详情 | 创建、审阅执行参数、执行、停止、验收 |
| 项目桌 | 当前项目、目标、任务记录 | 摊开项目任务，放入新想法草稿 |
| 交接路径 | 来源、接收员工、文件与目标 | 审阅交接，确认后创建下游草稿 |
| 工具架与素材盒 | 工具配置、接入状态、来源产物 | 配置、检查、预览、定位和交接 |

视觉采用纸感工作室与部门配色；工具陈设仅帮助辨认工作区，不表示已接通对应AI。提供两种空间氛围并保存偏好。任务和员工数据不随配色、缩放或布局变化。搜索通过⌘K定位空间对象。

拖拽草稿到员工只提出分配建议，确认后改变草稿负责人；必须提供键盘可用的同等操作。已执行记录不得静默换人。工作区成员在浮层中逐人展示，同区新增员工不覆盖已有席位配置。交接只有在来源任务已验收后才能确认，下游仍是草稿，不自动开始运行。装饰、布局关联线与真实交接记录须明确区分。

原生界面承载真实员工、工具、项目、任务与执行详情；草稿拖拽分配需确认，详情中提供相同的负责人选择操作。项目浮层展示真实交接与协作步骤，空间装饰连线表示布局关联。原型中未实现的原生功能明确标示为演示，不用示例任务填充原生空状态。

界面支持空状态、加载状态、错误状态和未配置状态，避免把示例内容当作真实执行数据。状态同时使用文字与颜色；日志可以选择复制；主要控件具备 VoiceOver 标签。支持系统深浅模式与键盘操作。

目标平台为 macOS 14 及以上，计划支持 Intel 和 Apple Silicon；当前先在 Intel 实机验证。主窗最小尺寸为 1100×720。性能验收在本机记录：10万行日志时界面可滚动、停止按钮仍可响应；M1 单进程，M2 再验证限制为2的并发模式。

持久化须保证工具、员工和任务重启后存在；写入失败明确报错。重启时执行中记录转为已中断，禁止自动再次运行，以免重复生成或重复付费。更新数据格式时带 schemaVersion；损坏数据须保留原文件，不能静默重建覆盖。

## 8 开发顺序与决策

工程使用 SwiftUI、Swift 核心与系统自带 SQLite。M1 的原子 JSON 迁移到 SQLite 时保留原文件和备份。执行器使用系统 POSIX 接口拥有进程组；不依赖 shell 拼接。仅在执行器明确存在瓶颈或跨平台需求时引入 Rust 或 Go；远程 Agent 与 ComfyUI 适配再引入 Python 服务。

| 顺序 | 主要交付 | 验收依据 |
| --- | --- | --- |
| 1 | PRD、设计规范、可点击原型 | 需求与页面逐项对应 |
| 2 | 可编译 Xcode 工程与本地执行器 | 构建成功和确定性进程测试 |
| 3 | 工具、员工、任务和日志基础功能 | M1 用例与实机检查 |
| 4 | 重试、产物、人工交接和权限细化 | 全部 P0 发布用例 |
| 5 | 远程ComfyUI、SSH连接与实际工作流 | 端到端真实验收 |
| 6 | AI拆解、依赖调度、审核与有限返工 | 真实多员工协作与中断恢复 |

开发按验收结果推进，不承诺依据概念规划就能估算固定代码量或完成日期。每个里程碑记录已完成、未完成和验证限制。

用户已授权按最优理解持续开发至M4，常规技术决策自行落实。默认本地CLI优先，AI规划与审核接入已登录的Codex；ComfyUI使用提供单任务取消接口的服务，SSH复用本机配置和密钥，仅绑定回环地址。服务器、工作流和测试预算属于实际远程验收的外部输入。产品使用My Workbench名称，本次交付为本机应用与工程；公开签名、公证和App Store分发不纳入默认范围。

## 9 远程制作与自动协作

ComfyUI工具配置保存服务地址、API格式工作流、执行超时、下载限额、预算说明和可选SSH隧道。工作流中的{input}作为JSON字符串替换，不执行模板代码。Bearer凭证仅保存在macOS钥匙串，工具、run与交接中只留配置引用。预算说明用于运行前核对，不能当作服务端计费上限。

提交前验证工作流与服务能力；提交前后保存稳定执行编号及服务端prompt_id。排队和执行状态来自队列与历史查询。停止调用按编号取消接口，再核对本任务已退出队列；不调用全局interrupt。断线或提交结果不确定时保留为已中断，恢复入口仅查询旧任务。远程文件显示位置和大小，用户主动下载；下载先检查上限，再核对完整大小，加入本次归档后才能验收。旧版服务缺少安全取消接口时提示兼容限制，不擅自影响其他任务。

AI规划员工以只读方式生成JSON计划，每个步骤记录员工、输入、验收标准和依赖。计划包含1至20步，必须检查独立编号、可用员工与工具、依赖存在性及无环。用户可以编辑后确认启动；确认前不执行生产步骤。调度器只启动已排队、依赖均已验收的步骤，向下游提供本项目对应run的已验收文件引用。

默认由用户逐步验收；用户可指定独立的AI审核员工，让审核达标后自动继续。审核接收当前候选和前序交付的归档证据，文本有单文件和总大小限额。缺少正文、内容被截断或媒体无法核查时，应暂停并请求人工检查，不能虚构已读取结果。审核输出pass、rework或blocked及证据说明，结论绑定来源run和审核run；过期结论不能修改新执行的状态。

每步自动返工默认上限1次，可设0至2次。返工生成新run，旧日志、产物与结论保留。达到上限、审核无法确认或执行失败时暂停后续步骤。暂停保留当前执行，停止整个计划则取消排队和运行中的作业；远程停止仍须确认服务端。重启不自动启动任务；用户确认继续后恢复尚未执行的步骤，已有执行的中断记录须单独检查。
