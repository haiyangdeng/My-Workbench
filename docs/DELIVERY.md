# Workbench 交付说明

应用名称为 **Workbench**，首字母大写。当前源码包含 PRD v0.6 的 M5–M9 实现；应用版本号保持 0.5.0、构建 8。这是本地候选构建，验收状态与已知问题见 [检查报告](REVIEW_2026-10-18.md) 和 [验证记录](VALIDATION.md)。

## 文件与启动

- `releases/Workbench-0.5.0-macOS.zip`：Universal 应用、PRD、使用说明和检查报告。
- `releases/Workbench-0.5.0-source.zip`：源码、Xcode 工程、测试、验证脚本和文档。
- `releases/SHA256SUMS.txt`：本轮两个压缩包的校验值。
- `MyWorkbench.xcodeproj`：工程和 scheme 名称保留，构建出的应用为 `Workbench.app`。

退出旧版应用后，打开解压所得的 `Workbench.app`。目标系统为 macOS 14 以上。应用使用本地 ad hoc 签名；Developer ID、公证与 App Store 分发不在本次范围。双架构构建不等于已经在两种硬件上实机验收。

## 首次使用

1. 在“工具连接”点“添加 CLI”。每个 CLI 都需手动配置可执行文件、每行一个参数的模板、输出格式及权限参数；参考 [PRD v0.6 附录 A](PRD_V06.md#appendix-a-example-cli-definitions)。npm 安装的 CLI 应开启“使用登录 Shell 的 PATH”。
2. 检测版本和登录。登录通过工具自身的终端流程完成；工作台不复制账号凭证。“发送测试提示”会使用工具账户额度。Codex 重试后成功仍可能显示失败，详见检查报告。
3. 新建 AI 员工并绑定 CLI，设置职责、工作区、最高权限及可选模型。
4. 在“项目”添加目录、分类和工作区。底部对话框选员工发送；多人可选择并行或团队，影像、声音、视觉项目可选导演。

只读和可编辑项目权限由用户填写的 CLI 参数实施。只有项目目录并不构成系统沙箱；员工最高权限与本轮请求共同限制实际使用的权限。

## 对话、协作与制作

对话支持续接、停止、排队、在终端继续和转为任务。团队先生成计划，用户审阅后启动；任务和计划步骤需验收。可编辑步骤可以使用独立 git worktree，验收后选择合并或放弃。

ComfyUI 需分别注册服务器与导入 API 格式工作流模板，配置参数和输出节点。可手动运行，也可由导演生成包含员工、生成和命令步骤的计划。服务必须支持按编号取消单个任务。凭证保存在钥匙串，SSH 隧道使用现有配置并绑定本机。

生成输出自动归档，支持图片、视频、音频预览、变体选择和导出。导演检查图片原图、视频关键帧与元数据；音频只提供元数据，不代表已经听审。预算边界存在本轮发现的问题；真实云 GPU 验收前应修复，详见检查报告。

## 数据与恢复

改名继续使用 `~/Library/Application Support/MyWorkbench` 与应用标识 `com.ocean.myworkbench`，已有 CLI、项目、员工和归档可继续使用。`workspace.sqlite` 保存数据，`Archives` 保存日志与产物。格式 4 升级前会创建 `workspace.pre-v06.sqlite`。

备份时先停止执行并退出应用，再整体复制该数据目录。损坏或不支持的数据会保留原文件并禁用写入。重启不会自动重发对话或生成请求。不要用旧版本写回升级后的数据库。

## 构建与验证

`zsh scripts/build.sh` 执行核心测试和 Debug 构建；产物为 `.build/xcode/Build/Products/Debug/Workbench.app`。`zsh scripts/package_release.sh` 构建 Universal Release、检查签名并生成交付包。

M5–M9 验证脚本使用隔离数据库与本地模拟服务。真实双 CLI 多轮协作、真实云 GPU 图像/视频/音频、点击与键盘操作、VoiceOver 及跨硬件验证仍需单独验收，不能由这些脚本或构建结果替代。

## 员工与各模块管理

本次补齐员工和工作区成员管理，并增加各对象删除、普通任务编辑、计划和产物重命名入口。详见 [对象管理说明](OBJECT_MANAGEMENT.md)。删除后对象退出日常列表；历史执行与归档文件保留。运行中、存在引用或远程状态未确认时，需要先完成相应处理。

## 深色外观

构建 8 统一深色背景、插画明度、文字与控件。沿用已有的浅色/深色设置，无需重新配置员工、CLI 或项目。
