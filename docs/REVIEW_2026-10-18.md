# Workbench PRD 检查与改名记录

日期：2026-10-18。检查对象：当前工作区源码、PRD v0.6 revision 2、M5–M9 验证脚本及构建/打包流程。

结论：M5–M9 的主要功能已有实现，自动验证能覆盖常规流程；仍有下列四项可复现问题和两项通过源码确认的需求缺口，因此当前构建应作为候选版本，不能标记为 PRD 全部验收完成。本次修改产品名称和对应交付配置，业务问题仅记录，没有顺带修复。

## 发现的问题

### P1：输入零预算会创建没有预算上限的制作计划

触发：制作计划审批中，GPU 分钟填 `0`、费用留空，点击确认。负数也有相同问题。

`ProductionApprovalSheet.approve()` 只检查数字能否解析及是否至少填一项，没有要求大于零；`approveProductionPlan()` 再把非正数转成 `nil`，并照常启动。结果是用户输入的限制被移除，生成任务可以继续提交。这违反 MD-18 的预算限制要求。

位置：`Sources/WorkbenchApp/ProductionViews.swift:108`；`Sources/WorkbenchApp/WorkbenchStore+Chat.swift:560`。

隔离复现：真实 store 接受了 `budgetMinutes: 0`，保存出的计划 `budgetMinutes`、`budgetCost` 都为空。通过占满模拟服务器的运行名额阻止实际提交，没有访问任何生成服务。

建议：界面与 store 同时校验预算是有限正数；存在 generate 步骤的计划至少保留一项有效上限。

### P1：运行中的多变体任务预算只按一个变体预留

触发：服务器允许两个任务同时运行。每个变体预计 1 分钟，计划上限 10 分钟，已启动的任务包含 8 个变体，另一个任务包含 3 个变体。

`canStartGeneration()` 对待启动任务乘了变体数，但对运行中任务只累加一次模板估算，因此把 8+3 分钟按 1+3 分钟计算，允许第二个任务启动。并且生成循环在每个变体提交前不会重新检查预算。这会导致预计总消耗超过用户批准的上限。

位置：`Sources/WorkbenchApp/WorkbenchStore+Media.swift:135`、`:138`、`:234`。

隔离复现：真实 store 对上述 10 分钟上限场景返回 `canStartGeneration == true`；预期应拒绝并暂停。没有实际提交任务。

建议：运行中的预算预留也乘以变体数，并在每次远程提交前重新检查。

### P2：Codex 重试后完成，连接测试仍显示失败

触发：Codex JSONL 先输出连接重试 `error`，之后输出回复 `ok` 和 `turn.completed`，进程最终退出码为 0。

解析器保留之前的 `errorMessage`，成功结束事件不会将其与终止失败区分；测试按钮又要求该字段为空，所以仍然显示“测试提示未成功”。此前本机真实测试已出现此现象，本次也用相同事件顺序通过真实解析器复现。

位置：`Sources/WorkbenchCore/CLIOutput.swift:138`、`:142`；`Sources/WorkbenchApp/WorkbenchStore+CLI.swift:99`。

建议：显式区分可恢复重试事件与 `turn.failed`，以最终终止状态判断成功，同时保留重试诊断。

### P2：继续编辑原本已经修改的文件，改动列表会遗漏

触发：用户在 Git 项目中已改过一个文件；员工在该文件上继续编辑。前后 `git status` 都是 ` M`。

`GitRepository.changedFiles()` 仅比较前后状态字符串。状态未变即被视为没有修改，导致 CH-11 所要求的本轮改动列表和差异入口遗漏这个文件。

位置：`Sources/WorkbenchCore/Git.swift:44`；`Sources/WorkbenchApp/WorkbenchStore+Chat.swift:269`。

隔离复现：真实临时 Git 仓库中，文件内容增加了员工写入的一行，状态前后都是 ` M`，实际返回的 `reportedFiles` 为空。

建议：比较轮次开始和结束时的内容或差异快照，不能只比较状态码。

## 尚未完全对齐 PRD 的部分

- **MD-16 导演资源范围选择缺失**：当前对话框只有导演开关，没有在规划前选择本次可用模板与服务器的入口。`productionSchema()` 和 `directorPrompt()` 使用全部模板与全部已启用服务器，也未按项目工作区或健康状态过滤默认范围。位置：`Sources/WorkbenchApp/ChatViews.swift:94`、`Sources/WorkbenchApp/WorkbenchStore+Chat.swift:429`。审批页能修改具体步骤，但没有实现 PRD 所述的规划前资源范围选择。
- **MD-02 运行中的健康信息未持续刷新**：`checkServer()` 按需检测，`startGeneration()` 只在缺少缓存时获取健康数据；远程执行循环轮询任务状态，没有更新服务器 GPU/显存/队列等 `serverHealth` 信息。位置：`Sources/WorkbenchApp/WorkbenchStore+Media.swift:54`、`:227`，`Sources/WorkbenchApp/WorkbenchStore.swift:433`。因此任务状态可更新，但服务器卡片的健康数据可能一直停留在旧值。
